# ADR 0014 - Group roots without changing session execution scope

- **Status**: Proposed (local implementation, 2026-11-07)
- **Context**: A workspace used to combine a folder path, Pi archive directory, settings key and navigation identity. That makes related repositories hard to keep together and can confuse a browsed folder with a session's actual execution directory. Pi 1.5.0 opens an archive in its stored header cwd, even when its process starts elsewhere. An umbrella parent folder cannot represent unrelated paths, and task-driven worktree orchestration adds lifecycle beyond the first useful slice of #5.
- **Decision**: Store local UUID root and group records in an atomic, versioned user-data registry. A group is an ordered collection of existing roots; a root can belong to multiple groups. Discover history using each archive header cwd rather than its storage directory. Keep model/reasoning defaults on roots. Validate requested root against archive header before resume/fork and recheck live ownership before prompts/model changes. Keep #33's exact-entry extraction and live archive-owner safeguards. Navigation never changes cwd or terminates a child; delayed opens become background tabs and unsent drafts remain at their original root. Persist group/root selection, but keep open children, views and drafts in memory.
- **Consequences**: Legacy workspace/default files are retained with backups; missing roots and their history stay visible. Invalid registry contents require recovery instead of silently resetting data. Root-scoped file previews retain containment; Pi tool execution still follows Pi/OS policy and is not sandboxed by group membership. Package-root commits are refused if the staged index includes changes outside the folder. Repository/worktree hierarchy, group-wide history, durable archive handles and cross-root context transfer remain later work. Relocating archives requires a separate #4 operation; a registry group does not move execution context. Filesystem replacement at an unchanged path cannot be reliably identified from path strings alone; automatic repair is outside this slice.
